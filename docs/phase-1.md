# SplitEase — Phase 1: Project Setup and UX Foundation

**Depends on:** `prd.md` (v1.1)
**Goal:** A clean, running Android app skeleton, connected to Supabase, with a proper design system, navigation, error/offline handling, and tests. No business features yet.
**Rule:** Work **one sub-phase at a time. STOP after each sub-phase**, run it on a real phone, and confirm before moving on.

> **Product stance:** SplitEase is **not a Splitwise copy**. The point of this app is a much better user experience: fewer taps, clearer language, easy add, easy undo. Phase 1 builds the foundation (theme, components, snackbar/undo, states) that makes that possible in later phases.

## 3. UX Principles (apply from Phase 1 onwards)

These guide every later phase. Each phase's acceptance includes "passes the UX checklist".

1. **Fast add:** adding an equal-split expense takes **3 taps or fewer**: amount → (smart defaults) → Save.
2. **Smart defaults:** payer = you, split = equal among all group members, date = today, description optional.
3. **Big, simple amount entry:** large number pad, opens automatically, no tiny fields.
4. **Undo instead of confirm:** deleting shows a snackbar "Deleted · UNDO" (we use soft delete, so undo is easy). No annoying "Are you sure?" popups for normal actions.
5. **Edit in place:** tapping an expense opens the same screen as "Add", pre-filled.
6. **Plain language:** "You owe Rahul ₹250", not "Balance: -250". No jargon.
7. **Show the effect before saving:** "Rahul owes you ₹250" preview on the add screen.
8. **No dead ends:** every empty state has one clear next action.
9. **One-hand friendly:** primary actions at the bottom of the screen (FAB, bottom sheets).
10. **Forgiving:** remember last used group, recent people, and last payer.
11. **Always show status:** loading skeletons, saving indicators, clear errors with a retry button.
12. **Never rely on color alone:** use text labels with green/orange amounts.

### [x] 1.2 — Supabase project and connection

**Goal:** The app can reach Supabase, keys are handled safely, and the migrations workflow exists.

**Tasks**
1. Create a Supabase project (region near India). Save the database password in a password manager.
2. Copy the **Project URL** and the **anon / publishable key** from the API settings. **Never copy or use the `service_role` key anywhere in this project.**
3. Create `.env` (git-ignored) and `.env.example` (committed, with empty values):
```
EXPO_PUBLIC_SUPABASE_URL=
EXPO_PUBLIC_SUPABASE_ANON_KEY=
```
4. Install packages:
```
npx expo install @supabase/supabase-js @react-native-async-storage/async-storage react-native-url-polyfill zod
```
5. `lib/env.ts`: validate the two env vars with Zod and throw a clear error if one is missing.
   - Gotcha: Expo only inlines `process.env.EXPO_PUBLIC_*` when it is accessed **statically**. Write `process.env.EXPO_PUBLIC_SUPABASE_URL` literally; do not read it dynamically like `process.env[name]`.
6. `lib/supabase/client.ts`:
```ts
import 'react-native-url-polyfill/auto';
import AsyncStorage from '@react-native-async-storage/async-storage';
import { createClient } from '@supabase/supabase-js';
import { AppState } from 'react-native';
import { env } from '@/lib/env';

export const supabase = createClient(env.supabaseUrl, env.supabaseAnonKey, {
  auth: {
    storage: AsyncStorage,
    autoRefreshToken: true,
    persistSession: true,
    detectSessionInUrl: false,
  },
});

// Pause/resume token refresh with app foreground state
AppState.addEventListener('change', (state) => {
  if (state === 'active') supabase.auth.startAutoRefresh();
  else supabase.auth.stopAutoRefresh();
});
```
7. Temporary connection check: a dev-only screen with a "Test connection" button that calls `GET {SUPABASE_URL}/auth/v1/health` with the `apikey` header and shows success or the error. (If that endpoint ever changes, use `supabase.auth.getSession()` plus a network call instead.) Remove or hide this screen before release.
8. Supabase CLI for migrations: `npm i -D supabase`, then `npx supabase init`, `npx supabase login`, `npx supabase link --project-ref <your-ref>`. Create an empty first migration with `npx supabase migration new init_schema`. From Phase 2 onwards, **every table, policy and function is created through a migration file in the repo**, never by clicking in the dashboard.
9. Add a note in `README.md`: free-tier projects pause after 7 days of inactivity, and free plans have no automatic backups, so take a manual backup before big changes.

**Acceptance**
- "Test connection" shows success on the real phone
- Removing an env var makes the app show a clear error instead of crashing silently
- `.env` is NOT in git (`git status` confirms), and `.env.example` is
- `supabase/migrations/` exists with the empty init migration

## 5. Reference: `formatMoney`

Money is always stored as integer **paise**. This function is **display only**.

```ts
export function formatMoney(amountMinor: number): string {
  const sign = amountMinor < 0 ? '-' : '';
  const abs = Math.abs(amountMinor);
  const rupees = Math.floor(abs / 100).toString();
  const paise = (abs % 100).toString().padStart(2, '0');

  // Indian grouping: last 3 digits, then groups of 2 (e.g. 1,23,456)
  const grouped =
    rupees.length > 3
      ? rupees.slice(0, -3).replace(/\B(?=(\d{2})+(?!\d))/g, ',') + ',' + rupees.slice(-3)
      : rupees;

  return `${sign}₹${grouped}.${paise}`;
}
```

**Required test cases**

| Input (paise) | Expected |
|---------------|----------|
| 0 | `₹0.00` |
| 5 | `₹0.05` |
| 12345 | `₹123.45` |
| 100000 | `₹1,000.00` |
| 12345678 | `₹1,23,456.78` |
| 99999999 | `₹9,99,999.99` |
| -250 | `-₹2.50` |

## 7. Common problems and fixes

| Problem | Fix |
|---------|-----|
| Metro shows old code or env vars are `undefined` | Restart with `npx expo start -c`. Env names must start with `EXPO_PUBLIC_` and be accessed statically |
| `adb devices` shows nothing or "unauthorized" | Reconnect the cable, accept the USB debugging prompt on the phone |
| "SDK location not found" | Set `ANDROID_HOME` and add `platform-tools` to `PATH`, then restart the terminal |
| Gradle or JDK errors | Use JDK 17, then `cd android && ./gradlew clean` and try again |
| Phone cannot reach Metro | Same Wi-Fi network, or run `adb reverse tcp:8081 tcp:8081` |
| "Network request failed" for Supabase | Check the URL starts with `https://` with no trailing slash, and that the phone has internet |
| First build is very slow | Normal. Later builds are much faster |
| Build broke after adding a package | Use `npx expo install <package>` (not plain `npm install`) so versions match the Expo SDK |
| Something is badly broken | Delete `android/` and run `npx expo prebuild --platform android --clean` |
